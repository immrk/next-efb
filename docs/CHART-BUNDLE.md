# NextEFB 航图分享包

NextEFB 航图分享包是以 `.zip` 为载体的版本化、多航图交换格式。它用于在用户社区间分享航图文件、地理配准和导航数据绑定，同时避免直接复制某一台机器上的导航数据库主键。

## 包结构

```text
NextEFB-charts-20260731.zip
├── manifest.json
└── charts/
    ├── 001-<chart-id-hash>/
    │   ├── source.pdf
    │   └── preview.png
    └── 002-<chart-id-hash>/
        └── source.png
```

`manifest.json` 的根字段：

- `format`: 固定为 `nextefb.chart-bundle`
- `schemaVersion`: 当前为 `1`
- `bundleId`: 每次导出的唯一 ID
- `exportedAt`: Unix 毫秒时间戳
- `producer`: 导出应用及版本
- `charts`: 航图清单

每张航图包含：

- 稳定航图 ID、标题、机场、类型、标题模式和时间戳
- 原始文件及可选预览文件的相对路径、格式、字节数和 SHA-256
- 最多两个地理配准点；每个点同时保存经纬度与图上坐标
- 跑道绑定名称
- 程序绑定的来源 ID，以及程序名称、程序类型和跑道组成的可移植语义描述

来源机器上的 `approach:<number>` 只用于诊断，不会被目标机器直接采用。

## 导入规则

导入分为预检和提交两个阶段。

1. 预检验证 ZIP 结构、格式版本、条目路径、CRC、资源类型、资源大小和 SHA-256。
2. 弹窗逐张列出航图，并按稳定航图 ID 标记为“新增”或“更新”。
3. 同 ID 更新即使包内 `updatedAt` 较旧也允许继续，但会明确提示用户。
4. 用户可以取消选择任意航图后再提交。
5. 航图资源、基础信息、地理配准点和绑定数据完整采用包内数据。
6. 跑道和程序绑定会优先根据目标机器的导航数据重新匹配；没有唯一匹配时保留包内原值，用户可在导入后自行调整。

绑定采用保守策略：

- 跑道：标准化 `RWY 09L`、`09L`、`9L` 后要求唯一精确匹配。
- 程序：程序类型、标准化名称和标准化跑道必须同时相等，并且目标库中只能有一个候选项。
- 来源数据库 ID 不参与跨机器匹配。
- 无匹配或出现多个候选时不做模糊猜测，直接保留分享包中的原始跑道名或程序 ID。
- 程序派生标题模式和包内标题始终保留，不因本机导航数据差异而降级。

## 一致性与限制

- 当前最多包含 200 张航图、500 个 ZIP 条目。
- 压缩包最大 256 MiB，单个解压条目最大 128 MiB，总解压大小最大 512 MiB。
- 不支持加密 ZIP、多卷 ZIP、ZIP64 或非 store/deflate 压缩方法。
- ZIP 条目不允许绝对路径、反斜杠或 `..`，避免路径穿越。
- 导入先写入暂存目录，再备份同 ID 航图目录并一次性提交数据库事务；文件或数据库任一步失败都会恢复原目录。
- 导入预检会话在 30 分钟后过期，避免长期持有已解压资源。
